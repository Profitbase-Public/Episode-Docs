# Hypergene InVision overview

The **Hypergene InVision** category contains the actions that integrate Flow with an InVision solution — the planning, budgeting, and forecasting platform. These actions cover everything from importing data into Dimensions and running Calculation Flows, to managing the Work Process Versions that drive a planning cycle, to running custom SQL or PowerShell scripts inside the InVision environment.

To use any InVision action, you first need an [InVision connection](./invision-connection.md). Connections come in two modes: a **Database connection** for actions that talk directly to the InVision SQL database (most data operations), and an **API connection** for actions that go through the public HTTP API — useful in environments where direct database access is restricted.

> [!IMPORTANT]
> [Execute Dataflow](./execute-dataflow.md) is included for migration purposes only. InVision Dataflows will be deprecated in a future version of InVision — avoid creating new ones, and prefer building business logic in Flow instead.

<br/>

## Calculation Flows

[Calculation Flows](./calculation-flow/overview.md) generate the data behind financial models — reading inputs and assumptions, running calculations, and writing the output back into InVision. This is the most extensive area of the category, with its own [overview page](./calculation-flow/overview.md) covering the full execution pipeline. Building a calculation involves configuring [Lookup tables](./calculation-flow/lookup-tables.md), [Distribution keys](./calculation-flow/distribution-keys.md), and [Auto transactions](./calculation-flow/auto-transactions.md) (with FilterByContext variants for both), then defining the [DB input](./calculation-flow/read-calculation-flow-db-input.md), [DB output](./calculation-flow/define-calculation-flow-db-output.md), and how the result is [saved back to the database](./calculation-flow/save-calculation-flow-output.md). Supporting concepts include [Data Context](./calculation-flow/data-context.md), [Table relationships](./calculation-flow/table-relationship.md), [Parameter relationships](./calculation-flow/parameter-relationship.md), and [Set lookups](./calculation-flow/set-lookups.md).

<br/>

## Working with Dimensions

Several actions read and update InVision Dimensions — the master data that organizes financial models. [Get Dimension DataReader](./get-dimension-datareader.md) returns a forward-only stream of rows from a dimension table, in either wide or parent-child format. [Load dimension tree](./load-dimension-tree.md) loads the entire dimension into memory as a parent-child structure for traversal and search. [Import data to Dimension](./import-data-to-dimension.md) writes data from a DataReader or DataTable (typically sourced from a CSV, Excel, Parquet, or external database) into a dimension, with options for handling user edits and empty values. [Publish Dimension](./publish-dimension.md) makes the changes available in the solution after an import. [Get Primary Dimensions](./get-primary-dimension-infos.md) lists the primary dimensions across all InVision solutions, useful for cross-solution maintenance flows. [Get database table name for Dimension](./get-db-table-name-for-dimension.md) returns the underlying SQL table name when you need it for direct database operations.

<br/>

## Working with Data Stores and Tables

[Get Data Store metadata](./get-data-store-metadata.md) retrieves metadata about a Data Store, useful for picking up execution context such as date ranges. [Run rollover](./data-store-group/run-rollover.md) shifts the data of a Data Store Group forward by a number of periods — typically used at the start of a new rolling forecast or budgeting cycle, and may include adjustments such as inflation. [Set Time Frame reference date](./data-store-group/set-time-frame-reference-date.md) defines the date a planning cycle applies from. For Tables, [Refresh Table artifacts](./table/refresh-table-artifacts.md) updates artifacts after data has been modified outside the standard import APIs (for example, by a SQL script). [Get database object name](./get-db-table-name-for-object.md) returns the underlying SQL name for an InVision object.

<br/>

## File Storage

InVision File Storage is used to keep files generated by or used by flows — typically exported CSV, Excel, JSON, or PDF documents. The actions cover the full lifecycle: [Add file to File Storage](./file-storage/add-file-to-file-storage.md), [Read file from File Storage](./file-storage/read-file-from-file-storage.md), [Delete file from File Storage](./file-storage/delete-file-from-file-storage.md), [Get file info](./file-storage/get-file-info-from-file-storage.md) and [Get multiple file info](./file-storage/get-files-info-from-file-storage.md) for retrieving metadata, plus context management with [Create File Storage context](./file-storage/create-file-storage-context.md), [Update file context](./file-storage/update-file-context-in-file-storage.md), and [Update files context](./file-storage/update-files-context-in-file-storage.md).

## Work Process Versions and Workflows

These actions automate the lifecycle of a planning cycle. [Create Work Process Version](./work-process-version/create-work-process-version.md) creates a new version in draft state, optionally copying structure and permissions from an existing one. [Deploy](./work-process-version/deploy-work-process-version.md), [Open](./work-process-version/open-work-process-version.md), [Close](./work-process-version/close-work-process-version.md), and [Delete](./work-process-version/delete-work-process-version.md) Work Process Version manage the version through its stages. [Start new Workflow iteration](./workflow/start-new-workflow-iteration.md) begins a new iteration of an InVision Workflow — typically used at the beginning of a new monthly, quarterly, or yearly cycle.

<br/>

## Package management

[Deploy package](./deploy-package.md) installs a Profitbase Store package (a `.pbpck` file) into a folder in an InVision instance — typically used to roll out a new release of a customer solution. [Upgrade package](./upgrade-package.md) upgrades an already installed package to a newer version using a `.pckup` upgrade file, and can also upgrade the package inside any versioned solutions it has been deployed into. For operations on whole InVision deployments — cloning a customer environment to test a deploy or upgrade before touching production, or tearing down a clone afterwards — see the [Hypergene DevOps](../hypergene-devops/overview.md) category.

<br/>

## Running custom scripts

When the standard actions don't cover what you need, two action groups let you run custom code inside the InVision environment. [Execute SQL Script](./sql-script/execute-sql-script.md), [Execute long-running SQL Script](./sql-script/execute-long-running-sql-script.md), [returning a single value](./sql-script/execute-sql-script-returning-single-value.md), or [returning a DataPackage](./sql-script/execute-sql-script-returning-datapackage.md) — pick the variant matching the expected runtime and result shape. [Execute PowerShell script](./powershell/execute-powershell-script.md) and [Execute long-running PowerShell script](./powershell/execute-long-running-powershell-script.md) do the same for PowerShell.

<br/>

## Deployment and conversion utilities

[Deploy Stored Procedure](./deploy-stored-procedure.md) and [Deploy View](./deploy-view.md) recreate a stored procedure or view based on its definition in InVision, useful for promoting database objects across environments. [Convert DataPackage to DataTable](./convert-datapackage-to-datatable.md) and [Convert DataTable to DataPackage](./convert-datatable-to-datapackage.md) translate between InVision's DataPackage format and the standard .NET DataTable used elsewhere in Flow — the bridge when moving data between InVision actions (such as [Execute SQL Script returning DataPackage](./sql-script/execute-sql-script-returning-datapackage.md)) and generic Flow actions (Excel, CSV, Parquet, SQL Server, etc.). [Apply synonym configurations](./data-pool/apply-synonym-configurations.md) applies the synonym configuration of a Data Pool object and its descendants.
